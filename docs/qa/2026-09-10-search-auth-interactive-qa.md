# 검색·인증 직접 QA (2026-09-10)

## 범위와 환경

- 로컬 프론트와 실행 중인 백엔드에 연결해 화면을 직접 조작했다.
- 데스크톱은 Chrome 및 인앱 브라우저, 반응형 화면은 인앱 브라우저의 425×950, 320×640에서 확인했다. Chrome의 화면 크기 변경 도구가 실제 뷰포트에 적용되지 않아 모바일 확인에는 사용하지 않았다.
- 사용자가 DB 데이터를 삭제했다고 알려주었다. 따라서 삭제된 계정·숙소 응답과 프론트 오류를 구분했다.
- 새 계정·숙소·예약 생성, 결제, 데이터 복원은 수행하지 않았다.

## 수정한 문제

### 로그인 실패 안내가 5초 뒤 사라짐

재현: 로그인 실패 → 폼 안의 오류와 토스트 표시 → 토스트 자동 종료 후 폼 안의 오류까지 사라짐.

원인: 로그인 모달과 인증 화면에서 토스트의 닫기 콜백이 폼 오류 자체를 지웠다.

수정: 토스트 닫힘 상태를 분리했다. 토스트가 자동으로 사라지거나 사용자가 닫아도 폼 오류와 재시도 버튼은 유지된다. 새 제출이나 폼 초기화 때 기존 오류가 지워진다.

- 수정 커밋: `320fafad`
- 실제 브라우저에서 5초 이상 지난 뒤 오류 안내와 재시도 버튼이 유지됨을 확인했다.
- 자동 종료, 수동 닫기, 동일한 오류로 재시도하는 회귀 테스트를 포함해 관련 22개 테스트 통과.
- 타입 검사, 변경 파일 ESLint, 변경 내용 공백 검사 통과.
- 기존 로그인 실패 테스트에서 React `act` 경고가 출력되지만 테스트 실패는 없었다.

| 삭제된 숙소 상세 진입                | 오류로 화면이 무너지지 않고 삭제·미존재 안내 표시              |

## 데이터 때문에 확인하지 못한 흐름

- 제공된 테스트 계정의 로그인 응답: “존재하지 않거나 활성 상태가 아닌 사용자입니다.”
- 검색 결과에서 연 숙소 상세 응답: “존재하지 않거나 삭제된 숙소입니다.”
- 검색 목록에는 결과가 남아 있었다. 검색 데이터와 상세 데이터의 동기화 여부는 이번 프론트 QA에서 확정하지 않았다.
- 로그인 성공 이후 위시리스트 추가·제거, 호스트 관리, 예약 견적·확정은 유효한 계정과 숙소 데이터가 준비되어야 실제 연동을 검증할 수 있다.

이번 결과는 위 범위의 점검 기록이며 전체 서비스의 기능 검증 완료를 의미하지 않는다.
