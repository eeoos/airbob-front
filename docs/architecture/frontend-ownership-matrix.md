# Frontend Ownership and Cutover Matrix

> Operational registry for the migration described by the active plan.  
> Baseline state: U4 commit `f5222d5`, followed by U5-U13, U19, U21, U22, U14, and U15 cutovers.
> Current cutover state: app Router/session/structural UI, every feature-owned data/workflow boundary, all route screens, and interaction accessibility are active; legacy global roots are retired; production Knip reachability and export ownership are globally strict.
> Current architecture meaning comes from
> [`current-frontend-architecture.md`](./current-frontend-architecture.md).

This file is deliberately mutable. Each implementation unit updates the rows it
owns in the same change that switches a production consumer. It records runtime
ownership; it is not a substitute for git history or plan progress.

## Registry rules

- **Active** is the only production route entry or mutation writer at this
  revision.
- **Compatibility reader** can read old data or project an owned result into a
  derived cache, but cannot perform a second backend/domain mutation.
- **Rollback** names the reader or artifact that makes a revert possible. It is
  never permission to mount old and new writers together.
- **Removal condition** must be satisfied in the named unit before a legacy
  surface is deleted.
- `none` means no compatibility layer exists or is required.

## Payment storage and rollback matrix

| Runtime | Records it may read | Writer | Rollback expectation |
| ------------------------- | ---------------------------------------------------------------------------------------- | ------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------- |
| Pre-U10 immutable build | Unversioned checkout/index and confirmed marker | Retired route/hooks | Current code does not read its records; rollback requires the whole immutable build |
| U10 immutable Toss v1 build | Owned/versioned checkout and callback records plus its historical migration input | Historical booking-payment aggregate | The immutable build reads its own records and is never mounted with current code |
| Current Toss npm v2 build | U10 versioned checkout/callback schema only; pre-U10 values are ignored and exact-prefix keys are purge-only cleanup input | booking-payment aggregate through v2 gateway only | Local gates are complete; Vercel Preview sandbox/OCI parity is explicitly deferred until the backend is available |
| Rollback to immutable U10 build | U10 records written before rollback | U10 aggregate through v1 gateway | Retryable checkout/callback reconciles through server status; v1/v2 are never active together |

If implementation needs a record shape that breaks this matrix, update the
active plan and browser-data inventory before changing a writer.
