This file is deliberately mutable. Each implementation unit updates the rows it
owns in the same change that switches a production consumer. It records runtime
ownership; it is not a substitute for git history or plan progress.
An **Active** runtime owner below records who runs today; it does not assert that
the owner's wire contract already matches `b2ec09a`. Rows change with the small
owner-switch unit that closes each current contract gap.

## Registry rules

- **Active** is the only production route entry or mutation writer at this
  revision.
- **Compatibility reader** can read old data or project an owned result into a
  derived cache, but cannot perform a second backend/domain mutation.
- **Rollback** names the reader or artifact that makes a revert possible. It is
  never permission to mount old and new writers together.
- **Removal condition** must be satisfied in the named unit before a legacy
  surface is deleted.
- `none` means no compatibility layer exists or is required.

## Payment storage and rollback matrix

| Runtime | Records it may read | Writer | Rollback expectation |
| --- | --- | --- | --- |
| Retired pre-v2 builds | Their historical unversioned or v1 records only | Retired direct-create/immediate-success writers | Current code never reads or migrates these records; exact prefixes are purge-only |
| First active v2 cutover | Exact v2 journal, callback credential, and operation receipt only | v2 booking/recovery transactions through Toss npm v2 | No pre-v2 build can interpret the active contract. Mutation remains fail-closed and recovery rolls forward until a verified v2-compatible revision is recorded |
| Later v2-compatible build | The same exact v2 schema/version and current backend V1 public contract | One v2 writer only | A rollback candidate must pass the deterministic matrix and prove journal/credential/receipt compatibility before deployment |

If implementation needs a record shape that breaks this matrix, update the
active plan and browser-data inventory before changing a writer.
